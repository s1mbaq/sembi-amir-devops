# Сценарий непрерывного видео

Цель: 12–17 минут. Записывай экран и собственный голос одним непрерывным видео.
Перед записью подготовь репозиторий и успешный пробный запуск Jenkins.
Открой два терминала: Linux-контейнер и Ubuntu WSL (на компьютере — Terminal), браузер GitHub, Jenkins и приложение.
Не показывай токены, административный пароль или личные вкладки.
Ниже текст для объяснения; произноси утверждения об успехе только после
того, как показал соответствующий результат.

## 0:00–1:00 Представление

Покажи Sembi_Amir_info.txt с настоящими значениями.

«Меня зовут Amir Sembi, моя группа IT2-2307, Student ID 37693.
Я показываю лабораторную работу по DevOps. В проекте связаны Linux, Git,
GitHub, Docker и Jenkins. Приложение показывает мои данные и имеет отдельный
адрес для проверки работоспособности».

## 1:00–4:00 Linux

Покажи `uname -s`, `pwd`, `ls -la`, каталоги и текстовый файл. Выполни
cp, mv и rm с учебной копией из COMMANDS_RU.md. Покажи head и tail.
Затем find, grep ERROR, grep WARNING, grep -c и последние пять строк.

«Для Linux-команд я использую Linux-контейнер. Проект лежит в домашней папке Linux-
пользователя. Find ищет файл по имени, а grep ищет текст внутри файла.
В этом учебном логе десять строк и два сообщения ERROR».

Покажи chmod и ls -l. Запусти системный скрипт.

«600 даёт владельцу чтение и запись. 644 дополнительно разрешает чтение
группе и остальным. Скрипт имеет право выполнения. Он показывает данные
студента, пользователя, hostname, дату, ОС, диски и память, а также проверяет
наличие информационного файла».

## 4:00–5:00 Процессы

Запусти sleep, покажи PID, USER, %CPU, %MEM через ps, затем top и выйди по q.

«Процесс — это запущенная программа. PID идентифицирует процесс. Ps выводит
снимок состояния, top обновляет его. У sleep низкая загрузка, потому что он
ожидает. Я показываю процессы Linux-контейнера».

## 5:00–7:30 Git и GitHub

Покажи git status, локальную identity, git log --oneline --graph --all,
ветки, `git show --stat development`, check-ignore и пустой вывод git ls-files.
В браузере покажи свой репозиторий и коммиты.

«Каждый коммит содержит отдельное изменение: структуру, персональные данные,
скрипты, приложение, Docker, Jenkins и документацию. В development я добавил
описание процесса и объединил его с main. Gitignore исключает логи, backup
и локальный env. GitHub хранит копию репозитория, откуда Jenkins получает код».

## 7:30–10:30 Docker

Открой Dockerfile. Покажи build, images, run, ps, logs и страницу приложения.
Объясни все шесть обязательных инструкций. Покажи значения окружения через
API, stop/start/exec, затем stop/rm. Запусти Compose, покажи ps и down.

«Образ содержит приложение и его среду. Контейнер — экземпляр этого образа.
RUN выполняется во время сборки, CMD — при запуске. EXPOSE описывает порт,
а параметр -p делает его доступным на компьютере. Через переменные окружения можно
менять данные без пересборки. Compose хранит настройки запуска в YAML».

## 10:30–14:30 Jenkins

Покажи имя job, Git URL, ветку main и Script Path. Открой Jenkinsfile.
Запусти Build Now. Пока он работает, объясни каждый этап.

«Checkout получает конкретный коммит GitHub. Build проверяет персональные
данные и компилирует Python. Test запускает десять тестов. После успеха
Docker Build собирает образ, а Docker Run запускает контейнер и проверяет
его HTTP-ответ. Переменные STUDENT_NAME, STUDENT_SURNAME, STUDENT_GROUP и
STUDENT_ID передаются приложению. При ошибке этапа дальнейшая сборка останавливается».

Покажи Console Output с данными, тестами, SHA и реальным Finished: SUCCESS.
Затем образ и контейнер через `exec jenkins docker images` и `docker ps`.
Открой localhost:8082.

«Этот контейнер работает в отдельном Docker daemon Jenkins. Поэтому для
просмотра я выполняю Docker-команды через Jenkins-контейнер. На порту 8081
находится Jenkins, а на 8082 — развёрнутое им приложение».

## 14:30–16:00 Завершение

Сравни commit SHA Jenkins с GitHub, покажи итоговый PDF со скриншотами.

«Linux предоставляет среду, Git сохраняет изменения, GitHub делает их
доступными Jenkins. Jenkins выполняет проверки, Docker упаковывает и
запускает приложение. Для сдачи я предоставляю репозиторий, PDF-отчёт и это
непрерывное видео. Я могу повторить команды и объяснить каждый этап».

После записи проверь, что слышен голос, читается текст и нет обрывов записи.
Не подменяй неудачную сборку текстом SUCCESS: исправь ошибку и запиши рабочую демонстрацию.
