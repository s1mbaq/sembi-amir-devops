# Ответы для индивидуальной защиты

1. **Создай новую ветку.** `git switch -c defense-demo-2` создаёт ветку от
   текущего коммита и сразу переключает на неё. `git switch main` возвращает назад.
2. **Найди файл.** `find . -type f -name 'application.log'`: точка — начало
   поиска, `-type f` — обычные файлы, `-name` — точное имя или шаблон.
3. **Найди ошибки.** `grep 'ERROR' logs/application.log`. Для количества
   строк использую `grep -c 'ERROR' logs/application.log`.
4. **Что значит chmod 755?** Владелец получает 7 = 4 + 2 + 1 = rwx.
   Группа и остальные получают по 5 = 4 + 1 = r-x. Для обычного скрипта
   это чтение и запуск без разрешения менять его другим пользователям.
5. **Pull и push.** Push передаёт мои коммиты в удалённый репозиторий.
   Pull получает удалённые изменения и интегрирует их в текущую ветку
   слиянием или rebase в зависимости от настроек.
6. **Образ и контейнер.** Образ — неизменяемый шаблон файлов и настроек.
   Контейнер — экземпляр с собственным изменяемым слоем и состоянием процесса.
   Из одного образа можно создать несколько контейнеров.
7. **Покажи логи.** `docker logs sembi-amir-container`. Для контейнера
   Jenkins сначала выполняю `docker compose -f infra/jenkins-compose.yml
   exec jenkins docker logs sembi-amir-container`.
8. **WORKDIR.** Устанавливает рабочий каталог для последующих инструкций
   Dockerfile и стартового процесса. В проекте это `/app`.
9. **Зачем gitignore?** Чтобы временные логи, backup и локальная конфигурация
   случайно не попадали в историю. Уже отслеживаемые файлы он не исключает.
10. **Объясни Test.** Jenkins вызывает unittest, который запускает десять
    проверок, включая реальные HTTP-запросы к временному локальному серверу.
    Ненулевой код завершения делает этап неуспешным.
11. **Если Docker Build упал?** Docker Run не выполнится. Jenkins покажет
    FAILURE и сообщение в Console Output. Исправляю причину, делаю commit/push
    и запускаю job снова. Старый контейнер на этой стадии не удаляется.
12. **Измени переменную.** Остановлю и удалю прежний учебный контейнер,
    запущу его с `-e STUDENT_GROUP=DEMO-GROUP`, проверю `/api/student`, затем
    восстановлю настоящую группу. Существующий контейнер не получает
    изменённый env автоматически.
13. **RUN и CMD.** RUN создаёт изменения в образе во время сборки.
    CMD задаёт команду по умолчанию для запуска контейнера.
14. **EXPOSE и -p.** EXPOSE документирует порт образа. `-p 8080:8080`
    связывает порт хоста с портом контейнера.
15. **Почему Python без pip?** Приложению достаточно стандартной библиотеки.
    Меньше внешних зависимостей, проще сборка и объяснение.
16. **Что здесь Build?** Проверка согласованности персональных данных и
    компиляция Python в байткод через compileall. Она не заменяет тесты.
17. **Почему Docker Compose?** Можно повторить запуск с теми же портами,
    переменными, сетями и томами одной командой по YAML.
18. **Зачем Jenkins GitHub?** Получить исходники и Jenkinsfile из известной
    ветки и зафиксировать SHA использованного коммита.
19. **Что сохраняется после выключения?** Исходники на компьютере, отправленные
    коммиты на GitHub и Jenkins в именованном volume. `down -v` удаляет тома,
    поэтому для обычного выключения его не использую.
20. **Почему два Docker daemon?** Docker Desktop запускает Linux и Jenkins.
    Отдельный DinD daemon собирает и запускает приложение по командам Jenkins.
    Это учебная изоляция; список его контейнеров нужно смотреть отдельно.
21. **Что обеспечивает безопасность?** Приложение работает без root,
    локальные порты привязаны к 127.0.0.1, Docker API Jenkins использует TLS.
    Пароли и токены не находятся в Git. Privileged DinD запускается только
    локально для этой лабораторной и не предназначен для недоверенного кода.
22. **Где доказательство, что код мой?** Личные данные, своя история изменений,
    собственный репозиторий, job, скриншоты и объяснение каждой команды.
    Автоматически подготовленные файлы нужно изучить и уметь воспроизвести;
    одна готовая папка не заменяет понимание.
